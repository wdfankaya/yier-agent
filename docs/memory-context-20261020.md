# 上下文与记忆修复记录（2026-10-20）

本次实现覆盖 ReAct、MultiAgent 和 LangGraph。不会把 ContextVar 当成共享状态锁，也没有把已有 finally/reset 误报为缺陷。

## 九项问题对应实现

| 原问题 | 实现与验证重点 |
| --- | --- |
| 消息条数不能约束输入大小 | 所有 llm_create/llm_parse 调用先做预算检查，包括工具定义、结构化输出 schema、消息开销；预留输出和安全空间。超限先移除可选记忆，再按完整轮次移除旧历史、提取大工具结果的业务字段；必要输入仍放不下时，在请求模型前报 context_budget。 |
| 按条保留可能切断语义 | 以 user 消息开始，保留其后全部 assistant/tool 消息，直到下一条 user；HISTORY_KEEP_TURNS 默认 3。压缩除条数阈值外也按预算触发。 |
| 摘要截断丢关键事实 | 不再调用模型生成 300 字自由摘要。原始消息存入按用户/会话隔离的 SQLite 证据档案；摘要抽取全部嵌套订单号、金额、成功/失败、状态等字段，不再只取工具结果前 200 字。超过摘要预算的证据仍留档，标明遗漏数量，可用记忆工具按关键词召回，或按来源 ID 查看原文。 |
| 错误摘要传播 | 每版摘要含版本、来源哈希、来源列表和排除列表；使用时核对原始来源并重建结构化摘要，不信任传入缓存文本。提供认证后的查看、来源原文、重建/排除来源接口；旧版本读取也尊重最新纠正。 |
| 偏好冲突 | 事实有 attribute/value/scope/status；同属性按原始观察时间、消息内位置确定当前版本，记录替代关系。支持常见喜欢/不喜欢/不再喜欢/不太喜欢/不偏好等更新；旧会话晚写不能覆盖新表达。每轮刷新也使 STM 与共享 LTM 对齐。 |
| 有效期缺失 | 普通偏好默认 90 天，临时偏好默认 7 天；“本次/这次”限定本会话。订单、退款、会员状态标为动态历史事实，不作为当前有效记忆召回，使用前要求调用业务工具重查。过期新偏好不会使旧偏好复活。 |
| query 无效、全量注入 | 提示词按本轮 query 做分词关键词过滤和 Top-K；工具支持 query/category/top_k，默认每类最多 5 条。历史原始证据也按查询匹配召回，且保留历史快照提示。 |
| 淘汰只取列表尾部 | 结合重要性、稳定性、来源置信度和最近访问/观察时间评分；召回更新使用时间。保留失效属性的版本头，防止淘汰后迟到旧写入复活。 |
| 来源和可信度不足 | 记录来源消息 ID、会话、原文、观察时间、来源类型与置信度；只提升可定位的用户明确表达和业务工具字段。旧无来源事实隔离，不再把模型推断注入为已确认事实。 |

## 并发、存储与重置

JSON：同一用户执行“读取最新状态 → 合并增量 → 原子替换”，同时使用进程内锁和操作系统文件锁。临时文件名独立，写入 flush/fsync 后替换。损坏文件报错，不覆盖原文件。

PostgreSQL：新增 memory_states_v2，以 user_id 为主键；INSERT ON CONFLICT 后 SELECT FOR UPDATE，在一个事务里合并 JSONB 状态。不同用户互不共用该行锁。已有 memory_facts 首次读取时按无证据旧事实兼容，不伪造来源。运行数据库模式前执行 `python -m alembic upgrade head`。迁移已通过离线 SQL 生成检查；后续已在隔离的真实 PostgreSQL 16.15 中通过 8 项并发与回滚测试，见 [验证与复现记录](memory-validation-20261020.md)。

长期记忆 reset 增加 generation 和 reset_at。已开始的旧写入因代次不一致被丢弃；刷新后重新提取的旧历史也因观察时间早于 reset_at 被拒绝。STM 使用本地锁，并在下一轮/工具召回时同步失效状态。

PG 的会话消息表没有保存自定义消息元数据的列，因此将观察时间和稳定消息 ID 存在已有 STM JSONB 内，以消息摘要核验后恢复。新 JSON 会话直接保留元数据。没有观察时间的旧 PG 消息不假定为新观察。

ContextVar 仍仅负责把工具调用绑定到对应 manager，finally/reset 保持。应用的会话注册表仍是单进程，以上记忆锁不代表整个服务支持多 worker。

## 配置与操作

新配置在 `.env.example`：CONTEXT_WINDOW_TOKENS、CONTEXT_OUTPUT_TOKENS、CONTEXT_SAFETY_TOKENS、HISTORY_KEEP_TURNS、SUMMARY_MAX_BYTES、SUMMARY_ARCHIVE_PATH、MEMORY_TOP_K、MEMORY_PREFERENCE_TTL_DAYS、MEMORY_TEMPORARY_TTL_DAYS、MEMORY_ARCHIVE_LIMIT。

默认窗口 32768、输出预留 2048、安全预留 512。计数采用 UTF-8 字节的保守估算和额外开销，不是供应商 tokenizer 的精确账单数。窗口必须按实际模型配置。单条用户输入/工具参数本身过大时明确拒绝，不静默截断用户要求或修改工具参数。可选摘要/记忆可因预算不足被省略；原始证据仍可查询。

认证后的接口（Authorization: Bearer 当前用户令牌）：

- GET `/api/sessions/{session_id}/summary`：当前有效版本、来源列表和结构化摘要。
- GET `/api/sessions/{session_id}/summary/sources/{source_id}`：查看该会话原始证据；其他用户不能读取。
- POST `/api/sessions/{session_id}/summary/rebuild`，请求 `{"excluded_source_ids":[]}`：从原文重新生成；传入来源 ID 则在后续版本中排除，不能指定其他会话的来源。

排除指的是纠正摘要证据，不会删除原始审计记录，也不等于修改当前业务订单。删除会话时删除对应的摘要档案。摘要 SQLite 文件在默认已忽略的 app/sessions 目录中，包含原始会话内容；不会写到测试报告。

## 能力边界

事实提取采用确定性的明确表达规则，优先避免误记。当前覆盖常见偏好、尺码与动态业务字段，不承诺理解任意复杂自然语言、反讽或隐含关系；不确定的表达保留在原始对话证据，不升级为确认事实。旧纯文本摘要因无法核验不继续注入；原始消息若已在旧版本被删除，无法凭空恢复。

摘要原文哈希用于检查来源与缓存是否一致，不是抵抗数据库管理员篡改的签名系统。证据档案按会话持续保存；活跃事实数量有限，非活跃审计条目有上限，但为阻止旧值复活，每个属性的最新失效版本头会额外保留。

后续已接入可选的 BGE 语义召回，与关键词排序结合；超时回退关键词，仍严格过滤来源、有效期和范围。小样本效果与配置见 [验证记录](memory-validation-20261020.md)。状态重查是召回策略和模型指令，真实业务操作仍须在业务系统校验授权、状态与幂等，当前项目订单/退款仍是模拟业务。

## 验证

运行 `python -X utf8 scripts/verify_upgrades.py`，机器可读结果见 `reports/upgrade-tests.json`。新增测试位于 `tests/test_context_memory.py`，包括调用前超限拒绝、完整工具轮次、大工具结果尾部金额、摘要来源篡改、版本纠正、过期/淘汰不复活、跨会话冲突、线程/多进程写入、reset 水位、STM 对齐、认证接口和三个 Agent 的完整对话路径。模型使用测试替身；文件锁、SQLite、HTTP 路由和 Agent 流程实际运行。该离线套件中的 PG 元数据适配仍使用模拟仓储；真实 PG 事务验证独立运行并记录在 reports/memory-postgres.json，不混入离线数量。

回归还发现并修复了 Windows 控制台编码错误可能在工具执行前抛异常的问题：诊断输出遇到无法编码字符时转义显示，不能因此把业务操作误记为结果未知。
